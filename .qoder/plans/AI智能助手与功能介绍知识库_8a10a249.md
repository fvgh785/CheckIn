# AI智能助手与功能介绍知识库开发计划

## 一、后端：数据库与核心逻辑

### Task 1: 新增 chat_history 表
- 文件: `backend/db.py` — 在 `init_db()` 中新增建表语句
- 表结构:
  - `id` VARCHAR(36) PRIMARY KEY
  - `user_id` VARCHAR(36) NOT NULL (FK → users.id)
  - `role` VARCHAR(16) NOT NULL ('user' | 'assistant')
  - `content` TEXT NOT NULL
  - `token_used` INT DEFAULT 0 (该条消息消耗的token数)
  - `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP

### Task 2: 新增系统配置项
- 文件: `backend/db.py` — 在 `init_db()` 初始化 `system_config` 的默认值部分，新增两行配置:
  - `chat_enabled` → `'1'` (全局开关，1=开启 0=关闭)
  - `chat_token_limit_per_day` → `'5000'` (每人每日Token消耗上限)

### Task 3: 新增 knowledge_bases 知识库表
- 文件: `backend/db.py` — 在 `init_db()` 中新增建表语句
- 表结构:
  - `id` VARCHAR(36) PRIMARY KEY
  - `title` VARCHAR(200) NOT NULL (知识库标题)
  - `content` TEXT NOT NULL (知识库正文)
  - `category` VARCHAR(50) NOT NULL DEFAULT 'general' (分类标签，如 feature/faq/announcement)
  - `enabled` TINYINT DEFAULT 1 (是否启用，0=禁用后不参与向量检索)
  - `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP
  - `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
- 初始化默认数据: 插入一条 `feature_introduction` 记录（完整功能介绍文本，category='feature'）

### Task 4: 向量数据库依赖与环境
- 文件: `backend/requirements.txt` — 新增 `chromadb`
- 文件: `backend/Dockerfile` — 无需额外改动（chromadb纯Python包，pip安装即可）
- 文件: `backend/chat.py` (新建) 中初始化:
  - Chroma 持久化目录: `data/chroma_db/`（已加入.gitignore的data目录下）
  - Embedding函数: 调用 DeepSeek API `https://api.deepseek.com/v1/embeddings`，model=`deepseek-chat`，复用 `AI_API_KEY`
  - 启动时从 `knowledge_bases` 表读取所有 `enabled=1` 的记录构建向量索引
  - 每条知识库记录作为一个独立 document，metadata 包含 id + title + category

### Task 5: 新增 chat.py 核心模块
- 文件: `backend/chat.py` (新建)
- 核心函数:
  - `init_vector_store()` — 从 `knowledge_bases` 表读取所有启用记录，每条生成 embedding 存入 Chroma（清空重建）
  - `rebuild_vector_store()` — 公开接口，供 admin 修改知识库后调用重建
  - `build_rag_context(user_message)` — 将用户问题 embedding 化，在 Chroma 中检索 Top-3 最相关片段，拼接为 RAG 上下文（含每条来源 title）
  - `chat_with_ai(user_id, messages)` — 构建 system prompt（注入RAG上下文），调用LLM，支持多轮对话（携带近10轮历史）
  - `check_chat_quota(user_id)` — 查询今日已消耗token
  - `use_chat_quota(user_id, token_used)` — 记录消耗，超过上限返回false
  - `get_chat_history(user_id, page, page_size)` — 分页获取历史对话
  - `save_chat_message(user_id, role, content, token_used)` — 存储单条消息
- 复用 `ai_insight.py` 中的 `AI_API_KEY` / `AI_API_URL` / `AI_MODEL` 环境变量
- System Prompt 模板: "你是每日打卡小程序的智能助手。请根据以下参考资料回答用户问题，语气温暖亲切，不超过200字。\n\n参考资料：\n{rag_context}\n\n如果参考资料不足以回答用户问题，请如实告知并建议联系人工客服。"

### Task 6: 新增聊天路由
- 文件: `backend/routes/chat.py` (新建)
- 接口:
  - `POST /api/chat/send` — 发送消息，返回AI回复 + 剩余额度
  - `GET /api/chat/history?page=1&page_size=20` — 获取历史对话
  - `GET /api/chat/quota` — 查询今日剩余额度
- 所有接口需 `@auth_required`

### Task 7: 注册新路由
- 文件: `backend/app.py` — 新增:
  ```python

  ```

## 五、Token消耗控制完整流程

### 对话Token消耗控制链路:
```
用户发消息 → 检查 chat_enabled 开关(关→拒) 
  → 检查今日token剩余额度(超→拒) 
  → 构建RAG上下文 + 对话历史 
  → 调用LLM 
  → 记录消耗量(user消息token + assistant消息token + RAG上下文token) 
  → 存储对话记录 
  → 返回回复 + 剩余额度
```

- Token估算策略: 由于DeepSeek/通义千问API返回中通常包含 `usage.total_tokens`，优先使用API返回值；若不可用则按字符数/2估算
- 每日0点自动重置（按 `chat_token_usage` 表按日期分区，查询当日消耗即可）

## 六、向量检索 RAG 架构

```
                          ┌─────────────────────────────┐
                          │  admin 后台 知识库 CRUD       │
                          │  新增 / 编辑 / 删除 / 禁用    │
                          └──────────────┬──────────────┘
                                         │ 变更后自动触发
                                         ▼
┌─────────────────────────────────────────────────────────┐
│              Chroma 向量索引重建                          │
│                                                          │
│  knowledge_bases 表 ──读取 enabled=1 记录──►              │
│  [功能介绍] [常见问题] [公告] [自定义...]                  │
│                         │                                │
│                         ▼ DeepSeek Embedding API         │
│                      向量存入 Chroma                     │
│                      持久化: data/chroma_db/              │
└──────────────────────┬──────────────────────────────────┘
                       │
        用户提问 ──► embedding ──► Chroma检索Top-3
                       │
                       ▼
              RAG上下文注入 System Prompt
                       │
                       ▼
              DeepSeek Chat API ──► AI回复
```
